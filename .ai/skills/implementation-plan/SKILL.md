---
name: implementation-plan
description: Plan a broad or risky PauseGuard implementation with explicit dependencies and validation. Use for multi-file features, architectural changes, migrations, or uncertain work.
---

1. State scope, non-goals, assumptions, and acceptance criteria.
2. Map relevant code and current architecture before proposing changes.
3. Split work into cohesive steps with clear dependencies and ownership.
4. Define build, test, simulator, visual, or manual evidence for every step.
5. Identify privacy, data migration, compatibility, and rollback risks where relevant.
6. Keep the plan proportional; do not force arbitrary line-count limits or parallelism.
